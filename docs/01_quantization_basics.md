# 01 · 量化入门：从 fp32 到 int8，模型为什么能变小变快

> 面向初学者。读完后你会理解：量化是什么、动态/静态量化的区别、为什么不同精度在不同硬件上快慢不同。所有结论都来自本项目的真实实验（MNIST CNN，200 万参数），复现命令见文末。

## 1. 什么是量化

神经网络训练时权重是 **fp32**（32 位浮点数）。量化就是把这些数换成更短的格式存储和计算：

![精度格式对比](../assets/quantization_concept.png)

- **fp32**：1 位符号 + 8 位指数 + 23 位尾数。指数位多 → 数值范围大（约 10^±38）；尾数位多 → 精度高。
- **fp16**：指数 5 位、尾数 10 位。范围小（约 ±65504），大数值会溢出。
- **bf16**：**指数位与 fp32 相同（8 位）**、尾数 7 位。范围和 fp32 一样大（训练时不易溢出），但精度低——这就是大模型训练偏爱 bf16 的原因。
- **int8**：纯整数 256 级（-128~127）。需要一个 **scale（缩放系数）** 把浮点范围映射进来。
- **int4**：纯整数 16 级。分辨率太粗，必须按 64~128 个权重一组各配 scale（per-group）才能保精度。

**整数量化（int8/int4）一个值的标准公式是三步：除以 scale → 四舍五入 → clip 到整数范围**（`q = min(qmax, max(qmin, round(x / s)))`）。前两步大家都能想到，第三步 clip 是必须的保险——不裁剪的话超出范围的值会溢出整数边界变成无关值。**所有静态量化的精度问题都出在这个公式对 s 的依赖上**，下面展开。

注意这个公式**只适用于整数量化**。fp16/bf16 是浮点格式，走的是另一条有损压缩路线——两者对比：

| 维度 | int8/int4 量化 | fp16/bf16 转换 |
|---|---|---|
| 公式 | `clip(round(x / s))` 三步 | IEEE 754 位域重排（一条硬件指令） |
| 需要 scale | **是**（整个方法的核心） | 否 |
| 误差来源 | round 到整数格 + 越界 clip | 尾数位变少（fp16 丢 13 位、bf16 丢 16 位） |
| 误差形态 | 绝对误差 ±s/2（均匀）+ 越界塌缩（有界） | 相对误差 ~2^-11 / 2^-8（大值误差大但成比例） |
| 溢出行为 | clip 截断（压到边界，还能用） | fp16 大值**上溢成 inf**；bf16 指数位与 fp32 相同、天然免疫 |
| 直觉 | 挪范围进格子（scale 是灵魂） | 换一套位域（指数保范围、尾数定精度） |

一句话：**两种完全不同的有损压缩**——fp16 训练要 GradScaler 而 bf16 不用，根源就是上表的溢出行为差异。

**量化的本质是牺牲精度换体积和速度**：一个 fp32 数字占 4 字节，int8 只占 1 字节——理论上模型直接缩到 1/4。

## 2. 两条路线：PTQ 与 QAT

量化方法先按**"要不要重新训练"**分成两条路线，这是所有量化算法的第一层分类：

| 维度 | PTQ（训练后量化，Post-Training Quantization） | QAT（量化感知训练，Quantization-Aware Training） |
|---|---|---|
| 核心思想 | 拿现成的 fp32 模型**离线测一测**就定 scale | 把 fake-quant 插进训练图，**边训边让权重适应量化** |
| 需要什么 | 少量校准数据（几百~几千张，不用标签） | 完整训练集 + 标签 + 训练资源（微调几个 epoch） |
| 成本 | 分钟级、零训练 | 本项目 3 epoch / 29 秒；大模型则数小时~数天 |
| scale 怎么定 | 统计校准数据的分布（min/max/分位数） | 训练中自动学出（observer 同步收集） |
| 精度 | 任务简单/分布匹配时无损；分布错配可掉数点 | 通常**优于** PTQ，甚至反超 fp32 基线（量化噪声当正则化） |
| 适用 | 快速部署、任务简单、拿不到训练管线 | PTQ 掉精度、精度敏感、训练管线可用 |

两条路线的**判断依据是同一个**：PTQ 的 scale 靠"猜"（统计校准分布），猜得准不准取决于分布匹配度；QAT 不猜——让梯度下降带着权重去适应写死的量化公式，模型自己找到对量化最鲁棒的解。所以工程实践是先用 PTQ（便宜），实测掉精度再上 QAT（本项目 Fashion-MNIST：PTQ 87.45% → QAT 93.95%，详见第 7 节）。

第 3~5 节讲的动态/静态量化都属于 **PTQ 内部的两个子类**——接下来看它们的区别。

## 3. 动态量化 vs 静态量化（本项目的核心实验）

两者都是"训练后量化"（PTQ，不需要重新训练），区别在于**激活值的 scale 什么时候确定**：

![动态 vs 静态量化工作流](../assets/dynamic_vs_static.png)

**动态量化**（`quantize.py`）：
- 只把**权重**提前转成 int8（导出时一次完成）；
- **激活保持 fp32**，推理时每个 Linear 层现场计算当前输入的范围再量化；
- 优点：不需要任何校准数据，简单；缺点：激活是 fp32，层间传输和计算没省，且只对 Linear 有效（Conv 支持弱）。

**静态量化**（`quantize_static.py`）：
- 先喂几百到几千张**代表性数据**（校准集），统计每层激活值的分布范围，把权重和激活的 scale **全部提前算好写死**；
- 推理时激活以 int8 形式在层间流动，全程整数运算；
- 优点：最快最小（Conv 也能量化 + 走融合 kernel）；缺点：校准数据不具代表性时会掉精度（见第 6 节的真实教训）。

### 用一个具体例子看两者的执行差异

设某一层 fc1 要算 `y = W·x`（W 是权重矩阵，x 是输入激活）。**"量化"指的是把浮点数变成 `int8 = round(fp32 / scale)`，scale 记录在旁边，算完再乘回去还原**。

**动态量化跑这层时**（权重提前量化，激活现场量化）：

```
部署时（离线，一次性）：
  W_fp32  ──→  W_int8 = round(W / s_w)，s_w = max|W| / 127   ← 写进模型

推理时（每次前向，逐层重复）：
  ① x_fp32 进来
  ② 现场统计范围：s_x = max|x| / 127          ← 这一步就是"动态"
  ③ x_int8 = round(x / s_x)                   ← 量化激活
  ④ int8 GEMM：y_int32 = W_int8 × x_int8      ← 整数乘加，快
  ⑤ 还原：y_fp32 = y_int32 × s_w × s_x        ← 反量化回浮点
  ⑥ y_fp32 传给下一层                          ← 下一层又要从 ① 重新来
```

**静态量化跑这层时**（scale 校准期算好，写死）：

```
校准时（离线，喂 1024 张图）：
  对每层激活观察统计 max|x| → s_x              ← 算好写进模型，推理时不再变

推理时（每次前向）：
  ① x_int8 进来（上一层输出已是 int8，直接用）
  ② int8 GEMM：y_int32 = W_int8 × x_int8      ← 同样的整数乘加
  ③ requantize：y_int8 = round(y_int32 × s_w×s_x / s_next)  ← int32 直接变下一层的 int8，不经浮点
  ④ y_int8 传给下一层
```

**三处关键差异**一目了然：

| 差异点 | 动态量化 | 静态量化 |
|---|---|---|
| s_x（激活 scale）哪来 | **每次前向现场算**（max 统计 + 除法 + round，全是开销） | 校准时算好，推理时查表 |
| 层间传递的数据 | fp32（算完就反量化回去了） | int8（requantize 直达下一层） |
| Conv 层 | 支持弱（Conv 的激活动态量化 kernel 不成熟），通常保持 fp32 | 与 Linear 同样量化 |
| 数值精度 | s_x 反映当前批次的真实范围，最准 | s_x 是校准集的统计近似，分布偏了就掉精度 |

这也解释了实测差距的来源：动态量化每个 Linear 层每批数据都要做 ②③⑤ 三次转换，且层间是 fp32 传输、Conv 保持浮点；静态量化把这些全部在离线付清，推理时 ①→④ 是纯 int8 链路（Conv 也一样），所以 0.563 ms → 0.242 ms。

**代价**：s_x 写死意味着如果真实输入的范围超出校准时的统计，量化值会饱和截断、精度受损。

### clip 到底做了什么：一个越界值的完整算例

量化三步里最不起眼的 clip，是理解静态量化风险的钥匙。接上面的例子：s_x 校准后定为 `1.40/127 = 0.011024`，推理来了个超出范围的值 `x = 5.2`：

```
除法：      5.2 / 0.011024 = 471.7
四舍五入：  round(471.7)  = 472
clip：      472 超出 [-127, 127]  →  强制置为 127
```

存进模型的 127，反量化回去只能是 `127 × 0.011024 = 1.400`。**真实值 5.2 被永久压成 1.40，误差 3.8 且不可恢复**。更糟的是 clip 是"塌缩"：5.2、3.0、2.0 所有越界值量化后都是 127，彼此再也无法区分。对比一个没越界的值——`x = 1.38` 量化后是 125，反量化 1.378，误差只有 0.002。**正常值的误差是 ±半个 scale（±0.0055），越界值的误差等于超出的整段，两者差三个数量级**。

在整批激活里看，clip 就是"削顶"：[0.9, 1.38, 5.2, 1.1] 量化成 [82, 125, **127**, 100]，那个 5.2 可能是笔迹特别深的强特征，削顶后与背景无异。个别值削顶，模型后续层的冗余能吸收（MNIST 同分布校准只掉 0.2%）；大片值集体越界（第 6 节的校准事故），精度就崩。

### 两种量化对"scale 失准"的免疫力对比

动态量化天然免疫截断风险：s_x 每批现场算，5.2 进来 s_x 就自动变大（0.041），量化后 `round(5.2/0.041) = 127`——**刚好卡在边界内，不丢信息**。代价是每层每次都要付这个统计的开销，且层间退回 fp32。

静态量化把 scale 写死，免疫不了，只能靠四层防御：

| 防御层 | 做法 | 原理 |
|---|---|---|
| ① 分布匹配（最重要） | 校准数据与真实输入同数据集、**同预处理/归一化** | scale 是统计量，分布对了统计才准 |
| ② 分位数截断 | Histogram/Percentile observer 用 99.9% 分位代替 max | 主动 clip 0.1% 长尾，换其余 99.9% 值的更细分辨率 |
| ③ per-channel 粒度 | 权重按输出通道各配一个 scale | 不同卷积核范围差几倍，一个 scale 顾此失彼 |
| ④ QAT | 训练时插 fake-quant，权重适应量化约束 | 让模型把重要信息搬离量化边界（见第 7 节） |

一个反直觉点：**不要为了"留余量防越界"故意把 scale 定大**。scale 大 = 步长大 = 所有正常值的误差按比例放大——留 2 倍余量，正常值误差翻 2 倍，只为保护可能不存在的离群值。正确思路是精确覆盖 99.9%，接受 0.1% 的有界截断。

本项目实测（CPU，i5-13490F）：

| 模型 | 大小 | P50 延迟 | 准确率（MNIST） |
|---|---|---|---|
| fp32 | 12.64 MB | 0.592 ms | 99.04% |
| int8 动态 | 3.44 MB | 0.563 ms | 99.05% |
| **int8 静态** | **3.20 MB** | **0.242 ms** | 98.98% |

### 优缺点总览

| | int8 动态量化 | int8 静态量化 |
|---|---|---|
| **优点** | 零校准数据、即拿即用；s_x 实时贴合输入，天然免疫截断 | 最快（2.3×）最小（3.20 MB）；Conv 也量化；层间 int8 传输；kernel 融合 |
| **缺点** | 只量化 Linear（Conv 保持 fp32）；每层每次付统计/转换开销；层间 fp32 传输 | 需代表性校准集；分布偏移时 scale 失准（四层防御见上） |
| **可量化层** | Linear | Conv + Linear（全图） |
| **精度风险** | 最低（scale 实时精确） | 取决于校准分布（同分布无损，错配掉数点） |
| **适合** | 快速集成、Linear 为主的模型（如 BERT 类） | 卷积模型、追求极限速度/体积的生产部署 |

静态量化比动态快 2.3 倍——因为 Conv 也被量化了（模型参数量大头在 Conv），且没有运行时量化的开销。

## 4. 混合精度：不是所有层都该降精度

两种混合精度策略的对比：

| 维度 | bf16 混合精度（`make_bf16_mixed`） | weight-only 量化（`bench_torchao.py`） |
|---|---|---|
| 做法 | 大部分层权重转 bf16，**敏感层保留 fp32** | 权重存 int8/int4，激活保持 bf16 |
| 敏感层/未量化层 | 首层 conv（接触原始像素）、全部 BatchNorm（统计量敏感）、最终分类层（logits 差一点就分错类） | 所有 Conv/Linear 权重都量化，激活不量化 |
| 体积 | 12.64 → 6.47 MB（约一半） | 12.64 → 3.45 MB（int8wo）/ 2.24 MB（int4wo） |
| 精度 | 无损（99.04% → 99.04%） | 无损（int8wo/int4wo 均 99.04%） |
| 速度（本实验小模型） | GPU ×2（Tensor Core）；CPU 慢 40 倍（无硬件支持） | GPU 持平 fp32（小模型上反量化开销抵消收益）；ResNet-18 上反超 4.27× |
| 适合 | GPU 训练与推理、大模型（不溢出） | 显存敏感的大模型推理；小模型收益有限 |

## 5. 量化后为什么精度几乎不掉

MNIST 任务简单（99% 基线意味着模型"余量"很大），int8 的 256 级分辨率足够表达每层权重的相对大小。实验中量化到 **int4（16 级）**精度仍然无损（99.04%，见 `tradeoff_scatter.png`）：

![体积 vs 精度权衡](../assets/tradeoff_scatter.png)

但这**不能推广到所有任务**——大模型的权重分布长尾更严重，对量化敏感得多。判断依据永远是：在你的任务上实测。

## 6. 真实教训：校准数据的分布必须与真实输入一致

在更难的 Fashion-MNIST（fp32 基线 92.68%）上重复了全部量化流程（`verify_fmnist.py`）：

| 模型 | 准确率 | 损失 |
|---|---|---|
| bf16 混合 | 92.68% | 0.00% |
| int8 动态 | 92.66% | -0.02% |
| **int8 静态** | **87.45%** | **-5.23%** ⚠️ |

bf16/动态量化的"无损"是普遍规律。静态量化掉的 5 个点，最初以为是校准数据不足——但校准研究（`calibration_study.py`）推翻了这个直觉：

| 校准场景 | 掉精度 | 加大数据量能否救回 |
|---|---|---|
| 同数据集，256 张 vs 16384 张 | 都只 ~0.2%，MinMax/Histogram 差异 <0.1% | 不需要（256 张就够） |
| 跨数据集（本事故：用 MNIST 数据校准 Fashion-MNIST 模型，归一化参数不同） | **5.3%**，且 16384 张错分布数据仍 5.6% | **救不回**（错分布的数据越多越确认错误） |

**生产准则：校准数据的分布与真实输入一致（同样预处理/归一化），比数据量和校准方法重要得多。** 校准掉精度的标准解法是 QAT（下一节）。

### 追问一层：预处理（标准化）为什么对量化这么致命

数据进模型前的 `Normalize((0.1307,), (0.3081,))` 是 `x' = (x - mean) / std`——**这本身就是一次"人为的 scale"**，和量化公式同族（减零点、除缩放）。由此看清事故机制：

1. **标准化保证激活范围稳定可统计**：0.1307/0.3081 是训练集的全局统计量，推理时沿用同一对数字，激活分布的形状和范围才可复现——校准统计出的 s_x 在推理时才依然有效；
2. **标准化参数错 = 输入分布系统性偏移**：对 Fashion-MNIST 用了 MNIST 的 mean（0.1307 vs 正确的 0.2860），相当于给所有输入平移了半个标准差——这不是统计噪声，是整体错位，校准的 s_x 从根上失配；
3. **顺带修正一个常见误解**：标准化并不会让数据"变成正态分布"——仿射变换只保证均值 0、方差 1，分布形状不变（MNIST 像素因大量黑背景本就是在 0 附近堆积的截断分布）。真正让深层激活近似正态的是中心极限定理（卷积输出是大量乘积之和）；而正态分布恰好由均值方差唯一决定，所以"标准化钉住矩 + CLT 保证形状"共同让各层激活范围稳定——量化 scale 才有可靠的统计基础。

一句话：**训练时的标准化和量化时的 scale 是同一件事（约束数值范围）在两个阶段的体现；前者错了，后者必然失准。**

## 7. QAT：静态量化掉精度的标准解法

QAT（量化感知训练）：把 fake-quant 节点插进模型，**边训练边让权重适应量化约束**。`qat_study.py` 在同一 Fashion-MNIST 任务上：

| 方案 | 准确率 |
|---|---|
| PTQ（校准错配） | 87.45% |
| fp32 基线 | 92.68% |
| **QAT（微调 3 epoch，29 秒）** | **93.95%** |

QAT 比 PTQ 恢复 6.5 个百分点，且**反超 fp32 基线 1.3%**（fake-quant 的量化噪声起到了正则化作用）。成本极低，是静态量化掉精度时的首选解法。

## 8. 部署引擎：为什么 TensorRT 能再快 30-100 倍

同样的模型，PyTorch eager GPU 吞吐 1.8k 条/秒，TensorRT 引擎 10 万+ 条/秒。差距不在精度，在**执行方式**：

![eager vs TRT 执行流程](../assets/precision_timeline.png)

| 提速来源 | eager 的问题 | TRT 的做法 | 收益 |
|---|---|---|---|
| 无 Python 分发 | 每个 op 走一次 Python→C++ 分发，小模型单层计算只要几微秒，分发占比 >80% | 引擎是编译好的 CUDA kernel 序列，一次调用执行整图 | 消除调度开销 |
| 算子融合 | Conv/BN/ReLU 每层单独执行，中间结果反复读写显存 | Conv+BN+ReLU 融合成一个 kernel | 消除中间显存读写 |
| kernel 自动调优 | 通用 kernel，不针对具体 GPU 形状 | 构建期对本机 GPU 实测几十种实现选最快 | 针对 28 个 SM 精调 |

**注意**：PyTorch 的 `quantize_dynamic` 只有 CPU 实现（依赖 oneDNN/FBGEMM），int8 想在 GPU 上跑必须走 TensorRT（QDQ 显式量化）或 torchao。

## 9. 快速选择指南

| 场景 | 推荐 | 理由 |
|---|---|---|
| CPU 部署 | **int8 静态量化** | 最快（2.4×）最小（3.2MB），注意校准集质量 |
| CPU 快速集成 | int8 动态量化 | 无需校准数据，精度最稳 |
| GPU（消费卡） | **TensorRT fp16** | 零精度损失、吞吐最高（32 万条/秒） |
| GPU 体积敏感 | TensorRT int8 | 3.3 MB，需校准集 |
| 静态量化掉精度 | **QAT 量化感知训练** | 本实验恢复 6.5% 且反超基线，成本极低 |
| 大模型训练 | bf16 混合精度 | 指数位与 fp32 相同，不易溢出 |
| 大模型显存敏感 | torchao weight-only | int8/int4 权重 + bf16 激活 |
