### ① fp16/bf16 转换的硬件成本（主线对应：[01 · §1](./01_quantization_basics.md#1-什么是量化)）

fp16 的位域重排（指数 8→5、尾数 23→10）有专用转换指令——x86 F16C 的 `VCVTPS2PH`（2012 年起）、ARM `FCVT`、GPU `cvt`，真·一条指令；bf16 因为就是 fp32 的前 16 位，GPU 上一条 `cvt` 或直接截断即可，**不支持 AVX512-BF16 的 CPU（如本机 i5-13490F）则退化为「把 fp32 当整数右移 16 位」的截断**——是普通整数运算而非转换指令。实战中权重通常在离线阶段就 cast 好写进模型，运行时几乎不付这个转换成本。

### ② 两种路线的误差长什么样，为什么 fp16 训练要 GradScaler（主线对应：[01 · §1](./01_quantization_basics.md#1-什么是量化) / [02 · §1.2 对比表](./02_quantization_advanced.md#12-浮点转换不是没有误差与整数路线的逐项对比)）

**误差形态**：int8 量化的误差是**绝对误差**——不管原值是 0.1 还是 100，误差都不超过半个 scale（±s/2，均匀分布），越界值被 clip 塌缩到边界（有界）；fp16/bf16 的误差是**相对误差**——尾数位数固定，数越大、绝对误差越大，但始终和数值成比例（fp16 约 2^-11、bf16 约 2^-8）。这两个数字的来历与整数路线的 s/2 完全同构，从「最小分辨率的一半」理解最直接：

- **bf16**：显式尾数 7 位 + 隐含首位 1 位 = 有效 8 位精度 → 相邻两格的相对距离（最小分辨率）约 2^-7 → round 取最近格、误差不超过半格 → **相对误差 ≤ 2^-8**；
- **fp16**：显式 10 位 + 隐含 1 位 = 有效 11 位 → 格距约 2^-10 → 半格 → **相对误差 ≤ 2^-11**。

与 s/2 的对应：两者都是「round 到最近格、误差 ≤ 半格」，差别只在格距的形状——整数路线格距均匀（绝对格距 s 恒定），半格误差是绝对值 s/2；浮点路线格距随数量级缩放（数值翻倍格距也翻倍），半格误差是相对值 2^-p。前者保证小值也准，后者保证大值不失真，两种保证不可兼得——这正是「需要 scale 的整数量化」和「不需要 scale 的位域重排」的本质差异。

展开看「±s/2 从哪来」。误差的唯一来源是三步里的**四舍五入**：除以 scale 得到的缩放值落在两个整数格之间，round 取最近的格，残差最多偏 0.5 个格，乘回 s 就是误差 ≤ ±s/2。以 [01 · §3.1](./01_quantization_basics.md#31-例子同一层-fc1-在两种量化下如何执行) 算例的 s = 0.011024 为例：

```
x = 0.37 → x/s = 33.57 → round 到 34 → 还原 34 × 0.011024 = 0.375
误差 = 0.37 − 0.375 = −0.005 ≈ 0.43 个格 × s   （≤ s/2 = 0.0055）
```

误差大小只取决于**离最近整数格差多少格**，与数值本身多大无关——这就是「绝对」误差的含义。假设另一层的 s = 0.85（量程 ±108，装得下 100）：

```
x = 0.1  → x/s =   0.12 → round 到   0 → 误差 = 0.12 格 × 0.85 ≈ 0.10
x = 100  → x/s = 117.65 → round 到 118 → 误差 = 0.35 格 × 0.85 ≈ 0.30
```

两次误差都 ≤ s/2 = 0.425：原值放大 1000 倍，误差上限不变（前提是不越界触发 clip）。对比 fp16 的相对误差就看出差别：值是 100 时，fp16 的绝对误差按比例放大到约 100×2^-11 ≈ 0.05；值是 0.1 时只有 0.00005——int8 的误差上限与数值大小**无关**（恒为 s/2），fp16 的误差上限与数值**成正比**。

「均匀分布」说的是**误差的分布**，不是缩放后的值落在 [−s/2, s/2]（常见误解）。当一批数据覆盖很多格点时，每个值的舍入残差落在 [−0.5, 0.5] 个格里各处的机会差不多，所以误差近似均匀铺在 [−s/2, s/2] 上——平均误差约 s/4，最坏 s/2。

**GradScaler**：fp16 的指数位只有 5 位，大值会**上溢成 inf**。训练时梯度更新量常小于 fp16 能表示的最小数（下溢变 0），所以必须用 GradScaler 把 loss 先放大一个系数，反向传播得到梯度后再除回系数（unscale）来更新权重；bf16 指数位与 fp32 相同、范围一样大，上下溢风险都小，不需要 GradScaler——这就是训练侧偏爱 bf16 的根源（与 [02 · §1.2 对比表](./02_quantization_advanced.md#12-浮点转换不是没有误差与整数路线的逐项对比)的「溢出行为」行对应）。

**为什么会"上溢成 inf"**——这是 IEEE 754 的编码机制，不是偶然现象。fp16 的 5 位指数能产生 0~31 共 32 个编码，协议规定：编码 0 表示零和次正规数（极小值），编码 1~30 是正常数（范围 2^-14 ~ 2^15），**编码 31（全一）被保留为特殊标记**——尾数为 0 表示 ±inf，尾数非 0 表示 NaN。所以 fp16 的正常数最大只能到 `(2 - 2^-10) × 2^15 = 65504`：这不是人为划的边界，而是"5 位指数能编码的最大数"的数学结果。运算结果一旦超过它，硬件只能返回编码 31（inf）。

inf 与 int8 的 clip 是两种本质不同的"装不下"：

| | int8 量化 | fp16 浮点 |
|---|---|---|
| 装不下的原因 | 8 位整数只有 256 个格子，scale 定了范围就锁死 | 5 位指数能编码的数值范围有限 |
| 装不下时硬件做什么 | **clip**：压到最近边界 127——结果"错误但可用" | **溢出**：返回 inf——结果是个失败标记，不是数 |
| 后续传播 | 误差有界（最多丢"超出的那一段"） | inf **污染后续运算**（inf × 0 = NaN，一个 inf 传染整层） |
| 是否可恢复 | 有界误差，模型可能容忍 | 不可恢复，必须防（GradScaler / 换 bf16） |

关键差别：**clip 是"数值域内的最近似表示"，inf 是"数值域之外的失败标记"**。bf16 之所以免疫：它的指数位 8 位与 fp32 相同，任何 fp32 装得下的数 bf16 都装得下，转换本身不产生新溢出——**bf16 用精度换范围，fp16 用范围换精度**，这就是训练选 bf16、推理常选 fp16 的根本原因。

### ③ 反量化为什么是"乘回去"（主线对应：[01 · §3.1](./01_quantization_basics.md#31-例子同一层-fc1-在两种量化下如何执行)）

由量化定义，权重和激活都是"真值除以 scale 再取整"（round 引入的误差先忽略）：

```
W_int8 ≈ W_fp32 / s_w
x_int8 ≈ x_fp32 / s_x
```

两式相乘（正是第 ④ 步做的整数 GEMM）：

```
y_int32 = W_int8 × x_int8 ≈ (W_fp32 / s_w) × (x_fp32 / s_x) = y_fp32 / (s_w × s_x)
```

也就是说 **y_int32 是"真值 y_fp32 除以 (s_w × s_x) 之后的商"**——量化时除法把真值缩小了 (s_w × s_x) 倍装进整数域，还原自然是把这个倍数乘回来：`y_fp32 = y_int32 × s_w × s_x`。除以 scale 量化、乘以 scale 还原，一除一乘互为逆操作。round 带来的偏差正是量化误差的来源——每个数最多偏 ±s/2，这就是本篇 ⑪（乘法与加法的精度行为差异）里"int8 乘加精确、误差全在量化映射"的含义。

### ④ requantize 公式怎么来的，s_next 和 s_x 为什么不同（主线对应：[01 · §3.1](./01_quantization_basics.md#31-例子同一层-fc1-在两种量化下如何执行)）

requantize 的推导和反量化完全同源。已知 `y_int32 ≈ y_fp32 / (s_w × s_x)`，把它**除回去**就还原出浮点真值：

```
y_fp32 = y_int32 × s_w × s_x        ← 这就是动态量化的 ⑤（反量化）
```

但静态量化到此**不停步**——下一层的输入要的是 int8，而这个 int8 是按下一层的 scale `s_next` 定义的：`x_next_int8 = clip(round(x_next_fp32 / s_next))`。把 `y_fp32` 代进下一层的量化公式：

```
y_int8 = clip(round(y_fp32 / s_next))
       = clip(round(y_int32 × s_w × s_x / s_next))   ← 把 y_fp32 用上一行替换
       = clip(round(y_int32 × (s_w × s_x / s_next)))
```

**三行就是 ③ 的全部来源**：把"反量化 + 下一层再量化"两步合并成一次乘法。四个 scale 全在部署期写死，所以系数 `(s_w × s_x / s_next)` 是一个**常量**，部署时直接算好存进模型，推理时只做一次乘法和取整。两个细节：

- **clip 不能省**：结果可能超出下一层的 [-127, 127]，越界要压回边界（机制见下文 ⑦）；
- **为什么这一步"便宜"**：对比动态量化的 ⑤+下一层的②——反量化乘两次 scale 出浮点、现场统计 max、再除再 round，一共四五个运算且经过浮点；requantize 只有一次乘法 + 一次 round + clip，全程整数域，还能直接融合进 GEMM kernel（"int8 GEMM → requantize → ReLU 一个 kernel"）。

**追问：s_next 是什么？和 s_x 一样吗**——不一样，且这正是 requantize 的关键。两者是**相邻两层各自的激活 scale**：

```
本层 fc1 输入 x 的范围：max|x| = 1.40  →  s_x    = 1.40/127   = 0.011024
本层 fc1 输出 y 的范围：max|y| = 0.42  →  s_next = 0.42/127   = 0.003307
```

`s_x` 是本层**入口**的刻度（决定 x 怎么变成 int8 进 GEMM），`s_next` 是本层**出口**（= 下一层入口）的刻度。两层之间隔着权重变换（放大/缩小信号）和 ReLU（砍掉负半轴），输出范围和输入范围没有任何理由相等。在 requantize 公式里两者分别出现在**分子和分母**——因为它是"用入口刻度定价的 int32，换算成用出口刻度定价的 int8"的刻度换算，就像经过两个汇率的换汇。若偷懒直接用 s_x 量化输出，下一层按 s_next 反量化时会系统性偏差 `s_next/s_x` 倍，逐层累积后信号幅度完全失真。这也是静态量化要**逐层**校准的原因：N 层模型有 N+1 个激活 scale（含网络输入）+ N 个权重 scale，每个"量化域边界"都要用自己的刻度。

### ⑤ 为什么对称量化只有 255 级，不是 256

int8 有 256 个位模式（-128~127），但本项目用到的对称量化把 scale 定为 `s = max|x| / 127`，映射区间是 **[-127, +127]，共 255 个格**（[量化原理图](../assets/quantization_concept.png) ① 面板画的正是这 255 个格）。

-128 这一格是被主动牺牲的，换来两件事：

1. **正负对称**：`q(−x) = −q(x)`，0 值精确映射到 0。若用满 -128~127（除以 128），正方向 127 格、负方向 128 格，天平歪一格——requantize 和硬件 kernel 都要额外处理这个不对称；
2. **乘加范围整齐**：±127 的乘积最大 ±16129，而 (-128)×(-128) = 16384，部分 int8 kernel（如 VNNI 路径）按 ±127 设计更省心。

用满 256 级的是**非对称量化**（0~255，激活值常用）：它不要求正负对称，但必须额外存一个 **zero-point** 来标定「浮点 0 对应哪个整数」。int4 同理：位模式 16 个（-8~7），对称量化只用 ±7 共 15 级。

### ⑥ int4 为什么必须 per-group 配 scale

int4 只有 15 个有效级（±7），一个 scale 覆盖整个权重矩阵时，步长被最大权重绑架：设某层权重范围 [-0.5, 0.5]，则 s = 0.5/7 ≈ 0.071——一个 0.02 的小权重除以 s 只有 0.28 个格，round 后直接变成 0，**这个权重被整个抹掉了**。相对误差动辄 100%+，这就是「分辨率太粗」的直观含义。

**per-group 的解法**：把权重按相邻的每 64~128 个分成一组，每组用自己的 max 算自己的 scale。分组之所以有效，是因为**相邻权重的幅值通常接近**——小组的 max 贴近组内真实范围，步长随之变小：

```
整层一个 scale：max = 0.5   → s = 0.071  → 0.02 的权重 round 到 0，彻底丢失
每 64 个一组：  组内 max = 0.1 → s = 0.0143 → 0.02 → clip(round(1.4)) = 1 → 还原 0.0143，误差 0.006
```

**代价**：每组要额外存一个 scale（通常 fp16），存储换精度——但相比把 4 bit 权重放宽到 8 bit 仍然省一半以上。torchao 的 int4 weight-only 就是这个方案（tinygemm kernel 推理时按组反量化），其小模型上不快、大模型上反超 4.27× 的实测数据见 [06 · torchao 与 ResNet-18 验证](./06_results.md)。

### ⑦ clip 的代价定量：正常值 vs 越界值差三个数量级（基础算例已上移 [01 · §3.1](./01_quantization_basics.md#31-例子同一层-fc1-在两种量化下如何执行)，此处只保留定量分析）

接 [01 · §3.1](./01_quantization_basics.md#31-例子同一层-fc1-在两种量化下如何执行) 的算例（s_x = 0.011024，x = 5.2 越界压成 1.40），把误差定量拆开对比：

- **没越界的值**（x = 1.38 → 125 → 反量化 1.378）：误差 0.002，即 ±半个 scale（±0.0055）以内——与数值大小无关；
- **越界的值**（x = 5.2 → 127 → 反量化 1.400）：误差 3.8，等于"真实值超出边界的整段"——值越大误差越大，无界。

**两者差三个数量级**，且越界误差随真实值增长而**无上限**。这就是为什么 clip 的风险必须单独评估：个别值越界（模型冗余能吸收，MNIST 同分布校准只掉 0.2%）与大片值集体越界（[02 · §2 的校准事故](./02_quantization_advanced.md#2-q3int-路线的真正风险校准数据的分布必须与真实输入一致)，精度崩）是两种完全不同的后果等级。

### ⑧ scale 失准的免疫力、防御与"scale 的最优选择"（主线对应：[02 · §2](./02_quantization_advanced.md#2-q3int-路线的真正风险校准数据的分布必须与真实输入一致)）

**免疫对比**——动态量化天然免疫截断风险（主流实现均用 max 公式）：s_x 每批现场算，5.2 进来 s_x 就自动变大（0.041），量化后 `clip(round(5.2/0.041)) = 127`——**刚好卡在边界内，不丢信息**。代价是每层每次都要付这个统计的开销，且层间退回 fp32。

静态量化把 scale 写死，免疫不了——四层防御见主线 [02 · §2 的防御表](./02_quantization_advanced.md#2-q3int-路线的真正风险校准数据的分布必须与真实输入一致)（分布匹配 / 分位数截断 / per-channel / QAT），此处不再重复。其中"分位数截断"值得展开：它不是防御，而是**主动进攻**——scale 的选择本身有优化空间（见下一小节）。

一个反直觉点：**不要为了"留余量防越界"故意把 scale 定大**。scale 大 = 步长大 = 所有正常值的误差按比例放大——留 2 倍余量，正常值误差翻 2 倍，只为保护可能不存在的离群值。正确思路是精确覆盖 99.9%，接受 0.1% 的有界截断。

**再进一步：scale 一定要取 max 吗——"故意变小、主动触发 clip"有时更好**

顺着这个逻辑推到底：既然留余量是赔本的，那么**主动把 scale 定得比 max 还小**（如取 99.9% 分位）是不是有时反而更好？是。scale 的选择其实是一个**优化问题**，两种选择的误差结构完全不同：

**取满 max（s = max/127）**：无截断误差，但步长 = max/127——离群值越大步长越粗，99.9% 的正常值陪着 0.1% 的离群值牺牲分辨率。

**故意取小（s = p99.9/127）**：步长按 p99.9/max 的比例变细，99.9% 的值舍入误差等比例缩小；代价是 top 0.1% 的值被 clip，误差从 ±s/2 变成"真实值 − 边界值"（有界但可能较大）。用 [01 · §3.1](./01_quantization_basics.md#31-例子同一层-fc1-在两种量化下如何执行) 例子的数字：

```
max|x| = 1.40，但 99.9% 的值 < 1.10

方案 A（max）：   s = 1.40/127 = 0.011024 → 0.37 的误差 ~±0.0055
方案 B（99.9%）：s = 1.10/127 = 0.008661 → 0.37 的误差 ~±0.0043（细 21%）
                  但 1.40 越界 → 压成 1.10，该值误差 0.30
```

方案 B 用 0.1% 的样本各背 0.3 的误差，换 99.9% 的样本每个省 0.0012——**样本量级完全不对等，只要越界样本确实稀少且后续层有冗余，B 明显划算**。这正是 Histogram/Percentile observer（四层防御之 ②）的原理：不是"怕越界才截断"，而是**截断本身就是换取分辨率的手段**。TensorRT 默认的熵校准（KL 散度）本质就是在自动搜索"截断损失 + 分辨率损失"总和最小的分位点。

什么时候该取 max、什么时候该取小：

| 数据分布 | 推荐 scale | 原因 |
|---|---|---|
| 单峰、长尾短（深层激活，CLT 保证近正态） | **分位数取小** | max 与 p99.9 差距大，截断收益高；尾部信息本来就少 |
| 长尾极重（个别值是典型值的百倍） | 分位数 + 更激进截断 | 保 max 会让步长荒唐地粗 |
| 双峰/多簇，越界的是一整簇 | 取 max（或加大组粒度） | clip 只对孤立离群友好；砍掉一整个合法模式等于删特征 |
| 分类层 logits（错一个就错结果） | 保守取 max | 尾部值可能恰在判别边界附近，截断直接改结果 |

本项目校准研究里 Histogram 比 MinMax 高 0.05%（92.51% vs 92.46%）就是这个方向上的收益——MNIST 上分布友好、收益小；激活长尾更重的大模型（attention map）上，分位数校准可差好几个点。

### ⑨ 预处理（标准化）为什么对量化致命（主线对应：[02 · §2](./02_quantization_advanced.md#2-q3int-路线的真正风险校准数据的分布必须与真实输入一致)）

数据进模型前的 `Normalize((0.1307,), (0.3081,))` 是 `x' = (x - mean) / std`——**这本身就是一次"人为的 scale"**，和量化公式同族（减零点、除缩放）。由此看清 02 · §2 事故的机制：

1. **标准化保证激活范围稳定可统计**：0.1307/0.3081 是训练集的全局统计量，推理时沿用同一对数字，激活分布的形状和范围才可复现——校准统计出的 s_x 在推理时才依然有效；
2. **标准化参数错 = 输入分布系统性偏移**：对 Fashion-MNIST 用了 MNIST 的 mean（0.1307 vs 正确的 0.2860），相当于给所有输入平移了半个标准差——这不是统计噪声，是整体错位，校准的 s_x 从根上失配；
3. **顺带修正一个常见误解**：标准化并不会让数据"变成正态分布"——仿射变换只保证均值 0、方差 1，分布形状不变（MNIST 像素因大量黑背景本就是在 0 附近堆积的截断分布）。真正让深层激活近似正态的是中心极限定理（卷积输出是大量乘积之和）；而正态分布恰好由均值方差唯一决定，所以"标准化钉住矩 + CLT 保证形状"共同让各层激活范围稳定——量化 scale 才有可靠的统计基础。

一句话：**训练时的标准化和量化时的 scale 是同一件事（约束数值范围）在两个阶段的体现；前者错了，后者必然失准。**

### ⑩ "大模型权重分布长尾更严重"是什么意思（主线对应：[01 · §4](./01_quantization_basics.md#4-q1量化会掉精度吗各模型的精度体积实测)）

这句话说的是**权重直方图的形状**——大部分权重挤在窄值域里，极少数离群权重拖出一条长尾。把两种模型的权重直方图画出来（横轴权重值、纵轴数量）：

```
MNIST 小模型（MnistCNN）——短尾：            大模型（如 LLM）——长尾：

数量                                         数量
 ████                                         ██████████████
 ████████                                     ██████████████████
 ██████████ ← 大多挤在 ±0.15 附近              ────────────────┤
 ────────────                                -0.02      0      ↑1.5
-0.3    0    0.3                                 绝大多数挤在 ±0.02，极少数
   max|x| ≈ 0.3，离群不远                        离群权重散布在 0.1、0.5、1.5
```

"长尾更严重" = **max 与典型值的距离被拉大**：小模型最大权重约为典型值的 2 倍，大模型可达 75 倍。成因包括：注意力头自发学出巨大的"特征选择"权重（LLM 的 activation outlier 现象）、词嵌入为区分数万 token 产生的个别大值、LayerNorm 让网络放心把某层放大而下层缩回。

**为什么直接影响量化**——步长 `s = max/127` 被最大值绑架，数字对比：

```
小模型（短尾）：max = 0.3，典型值 0.15
  s = 0.3/127 ≈ 0.0024 → 典型值 0.15/s ≈ 63 格（127 格用了一半，分辨率充裕）

大模型（长尾）：max = 1.5，典型值 0.02
  s = 1.5/127 ≈ 0.0118 → 典型值 0.02/s ≈ 1.7 格（99% 的权重挤在一两个格子上！）
```

大模型里 99% 的权重彼此无法区分——这就是 [01 · §4](./01_quantization_basics.md#4-q1量化会掉精度吗各模型的精度体积实测)"不能推广到大模型"最具体的机制。它也解释了两个对策为什么在大模型上是必需品：

- **per-group 分组（本篇 ⑥）**：离群值只污染它所在的那一组，其余组的 max 贴近真实范围；
- **分位数取小（本篇 ⑧）**：把 1.5 的离群值 clip 掉，步长立刻细 75 倍——大模型上收益是好几个点，MNIST 上只有 0.05%（短尾分布下 max 贴着典型值，没有压缩空间）。

## 硬件深水区（主线：[03 · 硬件架构](./03_hardware.md)，编号接续量化十问；⑮ 在文末，回到量化主线）

### ⑪ 乘法与加法的精度行为差异（主线对应：[03 · §4 精度格式对照表](./03_hardware.md#4-硬件-精度匹配矩阵把前面的现象收进一张地图)）

| 格式 | 乘法行为 | 加法行为 | 精度损耗发生在哪 |
|---|---|---|---|
| fp32 | 乘、加全程 fp32（乘积 48 位尾数里保留高位，加法逐位对齐） | 全程 fp32 | 无输入端截断；每步舍入到 24 位有效数字（误差 ~2^-24，基线） |
| tf32 | **输入先截断到 19 位**再进 Tensor Core 相乘 | 累加用 fp32 | 乘法输入端（每操作数丢 13 位尾数） |
| bf16 | 输入截断到 bf16（尾数 7 位）再乘 | 累加通常 fp32 | 乘法输入端（尾数只剩 7 位，误差 ~1%） |
| fp16 | 输入截断到 fp16（尾数 10 位）再乘 | 累加通常 fp32 | 乘法输入端（尾数 10 位，误差较小但可能溢出） |
| int8 | 乘法精确：int8×int8 的乘积完整落在 int32 里，**无任何舍入** | 累加用 int32，也是精确的 | **不在乘加**，而在量化映射本身（fp32→int8 的取整）和 requantize（int32→int8 再缩放） |
| int4 | 同 int8，乘法精确 | 累加 int32 精确 | 不在乘加，在量化映射（16 级取整，误差最大）+ per-group scale 恢复 |

### ⑫ 为什么是"24 位 × 24 位 → 48 位"？fp32 不是 32 位吗

32 位是**存储信封**的大小（1 符号 + 8 指数 + 23 尾数）；乘法真正作用于**尾数的 24 位有效精度**（23 位 + 规格化隐含首位——为什么隐含首位存在，见 [01 · §1](./01_quantization_basics.md#1-什么是量化)）。指数只决定小数点位置——相乘时指数直接相加，不占尾数。十进制类比（假设尾数只存 3 位）：

```
a = 3.14 × 10^2，b = 2.72 × 10^1
精确乘积 = 8.5408 × 10^3      ← 3 位 × 3 位 = 最多 6 位（类比 24×24 → 48 位"草稿"）
存回 3 位尾数 → 8.54 × 10^3   ← 舍入一次写回（类比舍入回 24 位）
```

加法同理：指数差决定对齐要移多少位，移出的低位由 3 个保护位（guard/round/sticky）临时接住，保证"如同无限精度算完只舍入一次"。所以 fp32 并非无损，而是**每次运算只舍入一次到 24 位**（误差 ~2^-24 级累积）；对比 bf16：输入在进乘法器前就被砍到 8 位有效数字，误差大一个数量级以上。

**关键洞察**：浮点格式（tf32/bf16/fp16）的精度损失发生在**乘法输入端**——数据一进来就被截断尾数，然后硬件用这些低位数相乘；而 int8/int4 的乘加本身是**精确的整数运算**（int8 乘积完整保留在 int32），损失全部发生在进入整数域之前的**量化映射**那一步。例：`(-37) × 96 = -3552`，int8 乘积完整落在 int32 里，一个 bit 都不丢——int8 推理的全部误差都在量化映射那一步（0.37 → 47 的取整），之后的乘加是纯精确运算。

这解释了两个实验现象：① int8 量化后精度无损（乘加不引入新误差，只有映射误差且 MNIST 上可忽略）；② fp16 训练需要 GradScaler（累加虽是 fp32，但输入端截断让小梯度更易下溢）。

**记忆要点**：bf16 和 fp16 同为 16 位，区别在指数/尾数的分配——bf16 拿尾数换指数（范围 = fp32，训练不溢出），fp16 拿指数换尾数（精度更高但会溢出，为什么 fp16 训练要 GradScaler 见本篇 ②）；int8/int4 不再是浮点，需要 scale 把浮点范围线性映射到整数级，int4 的 16 级分辨率必须靠 per-group scale（每 64~128 个权重一组）才能保住精度。

### ⑬ tf32：fp32 的"内部截断"加速路径（主线对应：[03 · §4 术语表 Tensor Core 行](./03_hardware.md#4-硬件-精度匹配矩阵把前面的现象收进一张地图)）

tf32 是 Ampere 引入的"内部截断"格式——数据仍以 fp32 存放（32 位信封不变），Tensor Core 计算时只取高 19 位（1+8+10）参与矩阵乘：范围与 fp32 相同，尾数精度与 fp16 相同，介于两者之间。Ampere 起 TRT 有 `TF32` 标志、PyTorch 有 `torch.backends.cuda.matmul.allow_tf32` 开关——**本实验均未开启**（所以矩阵图 GPU fp32 格子写的是"CUDA cores only"）。开启后 fp32 矩阵乘走 Tensor Core，速度接近 fp16，代价是尾数从 23 位降到 10 位。

### ⑭ AMX vs AVX512：同是"扩展"，层级完全不同（主线对应：[03 · §4 术语表 AMX 行](./03_hardware.md#4-硬件-精度匹配矩阵把前面的现象收进一张地图)）

| 维度 | AVX512（含 AVX512-BF16） | AMX |
|---|---|---|
| 本质 | 更宽的**向量**指令集（512 位寄存器） | **瓦片矩阵引擎**（tile 寄存器 + 专用加速器） |
| 编程模型 | 一条指令 16 个 fp32 / 32 个 int8，仍需自己组织循环 | 一条指令（`TDPBSSD` 等）完成整块矩阵乘（如 16×64 × 64×16） |
| 数据存放 | 普通向量寄存器 | 专用 tile 寄存器（2D 瓦片，软件配置形状） |
| 定位 | 通用 SIMD 的加宽版 | 接近 Tensor Core 的思路：把矩阵乘整个卸载给硬件 |
| 可用性 | 服务器 CPU（Ice Lake+ Xeon）；消费级 Raptor Lake 已砍掉 | 服务器（Sapphire Rapids+ Xeon）；消费级同样没有 |

一句话：AVX512 是「把 AVX2 的寄存器加宽一倍」，AMX 是「在 CPU 里塞了个 Tensor Core」。本机两者都没有，所以 fp16/bf16 只能靠 oneDNN 用 AVX2 模拟。

### ⑮ QAT 的 scale 从哪来——observer 统计 vs LSQ 梯度学习（主线对应：[02 · §3](./02_quantization_advanced.md#3-q3-的终极解法qat校准四层防御也不够时)）

QAT 训练中 scale 的"演化"有两种机制，区别在于 scale 是**被统计**还是**被优化**：

**observer 统计型（本项目 `qat_study.py` 用的 PyTorch FX 默认）**：可训练参数只有权重；scale 由 fake-quant 模块里的 observer 每个前向统计 min/max 得出——权重被梯度更新 → 权重分布漂移 → observer 统计出的 scale 跟着漂移。scale 是权重分布的"影子"：不进优化器、没有梯度。所以 01·§2 说 QAT"不猜"指的是权重适应了量化约束；scale 本身仍是统计量，只是统计窗口从"一次性校准集"换成了"整个微调过程"——从"给静止分布拍照"变成"给运动分布录视频"。

**微调循环具体在跑什么**（batch=256，3 epoch ≈ 700 步，每步四件事）：

1. **前向（带假量化）**：每个 fake-quant 点用**当前 scale** 执行 `x_fp = dequant(clip(round(x / s)))`——前向数值就是量化后的样子，loss 从第一步就"看见"量化误差；
2. **observer 同步统计**：observer 看的是 fake-quant 之前的**真实 fp32 张量**，按滑动平均更新 running min/max（`running_max ← 0.99×running_max + 0.01×batch_max` 量级）——scale 不跳变，随权重分布**平滑漂移**；
3. **反向（STE 直通）**：`round` 几乎处处导数为 0，普通反向传播的梯度会在量化点断掉——直通估计器（Straight-Through Estimator）把 round **当作恒等函数**传梯度（`d round(x)/dx ≈ 1`），让梯度穿过量化点继续流向权重。这是"能对着量化公式训练"的技术前提：没有 STE，权重一步都更新不了；
4. **优化器只更新权重**（+BN 参数）：scale 不在梯度路径里——它下一步的值由 observer 在**下一次前向**时重新统计决定。

对比 PTQ 静态校准的循环：只有第 1、2 步（前向 + 统计），没有第 3、4 步——**校准不动权重，QAT 动权重**，这正是两者 scale 统计窗口"静止照片 vs 运动视频"差别的来源。

循环的结果与"多快算够"：**scale 的合理化几乎不花时间**——observer 从**第一个 batch** 的 min/max 初始化，之后滑动平均只做平滑；只要微调数据分布正确（本实验用 Fashion-MNIST 正确归一化），头一个 epoch 内 scale 已是合理数值。700 步真正花在**权重适应**上：92.49%（用对校准数据的 PTQ 静态）与 93.95%（QAT）之间 +1.46% 的差距，才是权重对量化噪声的适应 + BN 统计量在量化链路上重新校准挣出来的。

**为什么这里 700 步就够——以及为什么这不是普遍保证**：三个本项目语境的原因：① 需要的修正量小——模型已训练好，正确 scale 下 int8 的量化噪声不大，lr=1e-4 的小幅微调足以收敛；② 任务余量大——Fashion-MNIST 基线 92.68%，过度参数化 CNN 冗余充足；③ 87.45→93.95 是**实测结果**而非推导。推广到大模型/更低比特时，没有"步数 → 合理 scale"的先验保证，常见做法是更长微调 + lr 调度、分阶段冻结、LSQ（scale 进梯度）、逐层敏感度分析——"多少步够"永远要实测。

**LSQ（Learned Step Size Quantization）/PACT 型**：scale 字面上就是可训练参数（`nn.Parameter`），用 straight-through estimator 把 round 的梯度直通给 scale，与权重一起被优化器更新——"把 scale 也当成权重"在这类方法里是字面事实。它解决 observer 型的局限：统计只能被动追着分布跑，梯度优化能**主动搜索误差最小的 scale**；比特越低（int4/int2）这个差距越大，所以 LSQ 主要用于低比特场景。

**共同点与终点**：两种 QAT 里 scale 都在训练闭环内演化（对比：PTQ 静态校准完即冻结、动态每批无状态重算）；convert 时 observer 移除、全部 scale 冻结，推理回到与普通 int8 静态完全相同的链路——这也是 QAT×动态组合语义错位的原因（训练时 fake-quant 按固定 scale 适应，推理换成现场算的 s_x 则公式不一致）。

一句话：**PTQ 静态 = scale 冻结（校准期定）；动态 = scale 每批无状态重算；QAT（observer 型）= scale 随权重统计演化；QAT（LSQ 型）= scale 作为可训练参数被梯度优化。**



### ⑯ BERT 类覆盖充分，但生产不用动态量化的四个原因（主线对应：[01 · §3.1](./01_quantization_basics.md#31-例子同一层-fc1-在两种量化下如何执行)）

"动态量化只量化 Linear，对 Transformer 覆盖充分"——覆盖 ≠ 最优选择。生产上 BERT 类更常用静态量化或 QAT/weight-only，四个原因：

1. **量化-反量化开销随深度放大**：动态每层每次前向都要"现场统计 max → 量化 → 算完反量化回 fp32"，层间 fp32 传输。330 万参数的小模型上这套开销可接受（与 fp32 打平），BERT-base 12 层、1.1 亿参数，每层的来回累积成显著负担；静态量化在校准期一次性付清，推理是纯 int8 链路。
2. **拿不到 kernel 融合**：静态 int8 的 int8 GEMM → requantize → GELU 可融合成单个 kernel（中间结果不落内存）；动态的激活 fp32 进出，每层都有显存往返。工业实测（Intel BERT int8 部署）：静态比动态有**数倍吞吐优势**，动态比 fp32 只有小幅提升。
3. **"激活范围随序列波动"对动态是伪优势**：动态用 max 公式，序列波动大意味着偶发离群值把 s_x 撑大，其余 99% 位置的步长被拉粗——与静态的"校准分布错配"同构的精度损失，只是从"校准时犯的错"变成"每批现场犯的错"。静态 + 分位数校准（Histogram observer）正是为"波动大但有稳定形状"的分布设计的。
4. **QAT 兜底精度**：公开数据（Intel/HF）BERT-base 静态 int8 + QAT 的 GLUE 损失 <0.5%，换来 3-4× 推理加速——精度代价已被覆盖，动态省下的校准工夫换不来部署收益。

一句话：**动态对 BERT 是"可行且精度稳"，不是"支持得最好"**——三个固有限制（每层量化-反量化开销、无 kernel 融合、层间 fp32）随深度线性放大；静态用一次校准前置所有开销、吃到融合 kernel，QAT 兜住精度。
