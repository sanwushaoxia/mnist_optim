## 数值格式

| 术语 | 白话解释 |
|---|---|
| 位 / 位宽 | 计算机存储数字用的「格子数」。8 位 = 8 个格子，每个格子只能放 0 或 1，所以 8 位能表达 2⁸ = 256 种状态 |
| 浮点数（fp） | 二进制版的科学计数法：不把数存成一长串 0/1，而是拆成「正负号 + 指数（管数量级）+ 尾数（管有效数字）」三段存——就像 3.14×10² = 符号 + 指数 2 + 尾数 3.14。二进制规范化后整数部分恒为 1、不用存（隐含首位），所以 23 位尾数实际有 24 位有效精度 |
| 符号位 | 三段里的第一段，1 个格子，只记正负 |
| 指数位 | 三段里的第二段，决定这个数「有多大/多小」（数量级）。指数位越多，能表示的范围越大 |
| 尾数位 | 三段里的第三段，决定这个数「有多少位有效数字」。尾数位越多，精度越高 |
| fp32 | 32 位的浮点数（1 符号 + 8 指数 + 23 尾数），训练模型时的默认格式，也是最准的基线 |
| fp16 | 16 位浮点（1+5+10）：指数位少 → 范围小（约 ±65504），大数会溢出；尾数位多 → 精度尚可 |
| bf16 | 16 位浮点（1+8+7）：指数位和 fp32 一样多 → 范围大不溢出；尾数位少 → 精度低。大模型训练爱用它 |
| tf32 | 「内部截断」格式：数据仍按 fp32 存，GPU 计算时只取高 19 位（1+8+10）参与矩阵乘 |
| int8 / int4 | 整数格式：8 位 = 256 个整数值，4 位 = 16 个。不是浮点，需要 scale 把浮点范围映射进来（详见 [01 · 第 1 节](./01_quantization_basics.md)） |
| 上溢 / 下溢 | 数太大超出了格式能表示的最大值（fp16 上溢会变成 inf），或太小低于最小分辨率（小梯度下溢变成 0） |

## 模型构件

| 术语 | 白话解释 |
|---|---|
| 权重 | 模型里学出来的可调数字（矩阵/张量）。200 万参数的模型 = 200 万个权重数字 |
| 激活 | 每层算完、流向下一层的中间数据。权重是「加工规则」（存死不变），激活是「正在被加工的料」（每来一张图都现算、都不同）：像素 → 第 1 层激活 → 第 2 层激活 → … → 分类分数。**注意激活 ≠ 数据集**：数据集是喂进模型的原料（只有输入一个位置），激活是原料经每层加工的中间产物（一张图会产生几十层各不相同的激活，每层范围不同、各配各的 scale）。静态量化要统计的就是每层激活的范围 |
| Conv（卷积层） | 处理图像的基本层：用小窗口在图上滑动扫描特征（如边缘、笔画） |
| Linear（全连接层） | 最普通的矩阵乘层：把上一层所有数字加权组合成下一层输入 |
| BN（BatchNorm） | 批归一化层：给每层数据拉回稳定的均值/方差。内部统计量（running_mean/var）对精度敏感，量化时永远保留 fp32 |
| logits | 最后一层输出的原始打分（每个类别一个分数），再经 softmax 才变成「是数字 7 的概率 99%」 |
| 矩阵乘 / GEMM | 神经网络计算的主体：W·x 这种「行乘列再求和」的运算。GEMM = General Matrix Multiply，工厂级的矩阵乘说法 |
| 算子（op） | 组成模型的基本计算单元：一个 Conv、一个 ReLU、一个矩阵乘各是一个算子。模型 = 一串算子按顺序执行 |
| kernel | GPU/CPU 上预编译好的一段并行计算程序。一个算子在硬件上由一个（或几个）kernel 执行；「kernel 融合」= 把几个算子合并成一个 kernel 执行，省去中间结果读写 |
| epoch | 训练时把完整训练集过一遍 = 1 个 epoch。本项目微调 3 epoch 就是把数据集完整过 3 遍 |
| batch | 一次同时喂给模型的数据条数。batch=1 逐条算（测延迟），batch=256 打包算（测吞吐） |

## 量化术语

| 术语 | 白话解释 |
|---|---|
| 量化 | 把 fp32 的数字换成更短的格式（int8/int4）存和算，换体积和速度（详见 [01 · 第 1 节](./01_quantization_basics.md)） |
| 反量化 | 量化值 × scale 还原回浮点数 |
| requantize | 不经浮点、直接从「上一层的 int8」换算成「下一层的 int8」，让整条链路保持整数 |
| scale（缩放系数） | 浮点范围和整数格之间的「汇率」。量化 = 除以它，反量化 = 乘回它。scale 既不是激活也不是权重——它是量化附带的换算参数，与权重一起存进模型文件 |
| zero-point | 非对称量化额外存的「零点偏移」：标定浮点 0 对应哪个整数值 |
| 校准 | 喂几百~几千张代表性数据，统计每层激活的范围，从而定下 scale。只做统计，不训练 |
| fake-quant | 量化感知训练时插进模型的「假装量化」节点：前向按量化值算（让权重提前适应取整误差），反向仍用浮点更新权重 |
| QDQ（显式量化） | 在模型图里显式插入 Quantize/Dequantize 两种节点，明确标出「哪里变 int8、哪里变回浮点」。TensorRT 11 构建 int8 引擎要求的格式 |
| PTQ | 训练后量化：模型练完、不再训练，离线测一测就定量化参数（详见 [01 · 第 2 节](./01_quantization_basics.md)） |
| QAT | 量化感知训练：把 fake-quant 插进训练图，边训边让权重适应量化（详见 [01 · 第 7 节](./01_quantization_basics.md)） |

## 性能与硬件

| 术语 | 白话解释 |
|---|---|
| 延迟 | 处理 1 条数据要多久（ms/条）。在线服务（用户等结果）看它 |
| 吞吐 | 每秒能处理多少条（条/秒）。离线跑完一个数据集看它。和延迟不是倒数关系 |
| P50 / P95 / P99 | 把 200 次测量的延迟从小到大排队：P50 = 排在正中间的值（中位数），P95 = 95% 的请求快于此值，P99 = 99%。P99 远大于 P50 说明偶尔有极慢的「长尾」（详见 [03 · 第 2 节](./03_reading_benchmarks.md)） |
| SIMD | 单指令多数据：CPU 的一条指令同时对 8 个/32 个数字做同样的运算。CPU 上算神经网络靠它提速 |
| CUDA core | NVIDIA GPU 里的通用计算单元（RTX 3060 有 3584 个），fp32 在这里跑 |
| SM | 流式多处理器：GPU 的「车间」，每个 SM 内含若干 CUDA core 和 Tensor Core |
| Tensor Core | GPU 里专做矩阵乘的固定功能电路（fp16/bf16/int8/int4），吞吐远超通用单元，但没有 fp32 模式 |
| TFLOPS | 每秒一万亿次（10^12）浮点运算，衡量算力的单位。A100 的 Tensor Core 是 312 TFLOPS |
| 显存带宽 | 显存每秒能搬多少数据（RTX 3060 约 360 GB/s）。小模型推理常卡在搬数据而非算 |
| JIT | 即时编译：第一次运行时才把代码编译成机器码，所以前几次调用特别慢（计时必须丢弃预热） |
| 拓扑序 | 模型图里算子的执行顺序：必须先算出输入、才能执行消费它的节点 |

## 工具链

| 术语 | 白话解释 |
|---|---|
| PyTorch eager | PyTorch 默认执行方式：每个算子单独走一遍 Python→C++ 分发，灵活但慢 |
| autocast | PyTorch 的自动混合精度开关：`torch.autocast(bfloat16)` 自动把 conv/GEMM 派给低精度执行 |
| GradScaler | fp16 训练的梯度放大器：loss 先乘一个大系数防下溢，更新权重前再缩回来。bf16 不需要 |
| oneDNN / FBGEMM | CPU 深度学习算子库（Intel 出品 / Meta 出品），PyTorch CPU 量化的底层实现。只支持 CPU，没有 GPU 版 |
| ONNX | 模型的通用交换格式：从 PyTorch 导出成 .onnx 文件，才能喂给 TensorRT 等部署引擎 |
| TensorRT（TRT） | NVIDIA 的推理引擎：把整图编译成优化的 kernel 序列，比 PyTorch eager 快 30-100 倍（详见 [02 · GPU 上发生了什么](./02_hardware.md)） |
| 强类型引擎 | TensorRT 构建时就锁死输入输出数据类型（如 fp16 引擎的输入必须是 HALF）、运行时不可更改的引擎 |
| torchao | PyTorch 官方的量化工具包，提供 int8/int4 weight-only 量化（权重低精度、激活保持 bf16） |
| torch.compile | PyTorch 的图编译开关：把 eager 模式编译成更快的执行图，CPU 上约 15-40% 提速 |
